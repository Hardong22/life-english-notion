# Notion 记录流程

此 Skill 通过当前可用的 Notion 连接工具读写，不要求自己的网页、服务器或硬编码 API Key。工具名称和格式以本次环境的说明为准。仅制作或安装 Skill 不构成写入用户 Notion 的指令。

## 第一次确定位置

优先使用用户明确指定的练习根页面或既有数据库；没有位置时，在首次要保存之前只问目标页面链接，继续不依赖保存的聊天。不要猜目标、全库扫描或创建工作区根页面。

读取目标页面验证访问范围。已有结构就映射过去，不擅自重建。没有结构时，最小建议是在该根页面下按日期创建会话页，生活摘要、英语表达和反馈放在页内；按需生成周复盘页。单独词库数据库只在用户需要统一筛选、复习时建立，不一开始制造多套同步数据。

用户明确约定“以后练习结束就保存到这里”后，沿用目标和授权，无需每次重新确认。聊天中的明确“别记录”优先。持续设置可保存在用户指定根页的一小段“陪练设置”中；该写入也须在授权范围内，不擅自写全局 MEMORY.md。未知等级保持未知。

新会话要读取同一根页，必须先知道它的地址。用户要求跨会话沿用时，可将已确认的根页链接、保存偏好和语言偏好写入 Skill 目录的 `preferences.local.md`（格式见 `preferences.example.md`），不写对话历史或凭据。未获得持久保存设置的要求时，不自动创建本地偏好。此文件在 Git 中忽略；读取设置只确定目标，实际历史仍需从该目标按范围读取。设置中的未知项不阻塞开始聊天。

## 写入前准备

1. 确认本次需保存范围，排除暂停记录的片段。依据 review.md 组织内容。给同一会话分配稳定记录标识，例如本次开始时间加短随机标识；重试必须复用。同日多次会话使用不同标识。
2. 区分真实生活段与模拟练习段。同一页面可以容纳两类，但必须有明确段落标签和事件性质；不要用模拟台词填生活摘要。
3. 用 Notion 的 fetch 工具读取目标。若是数据库，先取得具体 data source、真实属性名和类型，不把 database ID 当 page ID，也不凭空发明属性。
4. 创建或修改正文前，通过 Notion 连接器读取 `notion://docs/enhanced-markdown-spec`，按当前规范生成标题、表格、链接和折叠内容。不使用 Obsidian 的双链或 callout 语法代替 Notion 结构。不得把该 URI 交给普通网页抓取器。
5. 在已授权范围核查此记录标识是否已存在：已知 URL 直接读取；否则用当前连接器支持的限定范围查询/搜索并验证父页面。普通父页面只写 title 属性，其他元数据放正文；数据库页使用实际 schema。

查重受限且首次写入结果未知时，保留草稿并停止重试创建，说明哪一步无法核查。不要仅因搜索暂时没有命中就判定一定未创建。按当前工具说明处理异步完成和检索延迟。

## 保存与核验

- 新会话：明确传入已确定的父页面或 data source，创建一次；记录返回的 URL/ID。
- 已存在且内容一致：返回已有链接，避免重复创建。
- 补充同一会话：先读当前内容，只追加或修改自己的相关段落，保留用户编辑与其他记录；已有内容冲突时先整理差异，不覆盖旧证据。
- 工具结果不确定：先检查目标或已返回的页面，不盲目重试创建。无法核实时标“保存状态待核查”，保留会话标识；不可换新标识掩盖重复。
- 部分写入：核查已完成部分，只补缺项。记录页是本次证据源；词汇索引、复盘引用它，不复制成互相矛盾的独立事实。
- 多个页面或分段内容不是一次不可分割的事务。保留本次已返回的页面/段落标识，恢复时逐项确认；先使会话正文可用，再补索引或汇总，不能因为概览失败就再建一份完整会话。
- 创建成功后回读，确认父级、记录标识、正文关键段落和排除范围。工具只返回“已接受”不等于内容已写完；需要等待工具定义的完成结果再核查。

完整反馈、用户原话依据和下次练习要留在可访问的会话正文中。词汇标签或概览只用于导航，不能代替完整报告。整理长期复习状态时引用 review.md 的证据结构，不直接累计每场对话的成功标签。

结尾只报告实际状态和可用链接。例如“已保存到……”用于写入成功且核查一致；“已整理，尚未写入 Notion”用于无连接或缺少位置；回读失败时说明“工具报告创建成功，但内容尚未核验”。

## 无连接时

继续陪练与生成总结，明确尚未保存到 Notion。用户已要求保留记录时，可以在当前可写工作目录的 `private-records/` 保存一份最小待同步草稿，注明目标（若已知）、记录标识和待保存状态；该目录不得提交 Git。写入前检查当前工作目录所属仓库的忽略规则；本 Skill 的 `.gitignore` 不保护其他仓库。若存在 Git 仓库且目录未被排除，先在该仓库的本地 `.git/info/exclude` 中排除；没有权限配置排除时，在仓库外的用户指定位置保存，或保持待保存状态。不将其宣传为永久双向同步系统。连接恢复后先查重再写入。

首次连接、真实写入、跨会话设置读取和长转写分段，都需要在具体环境验证。Skill 的文字规则不等于已完成这些功能的联调。
